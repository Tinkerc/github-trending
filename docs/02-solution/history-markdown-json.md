# 历史 Markdown 提取与 JSON 归档

## 原始 Markdown 压缩归档

新增 `archive_markdown.py`，按年份将根目录 `YYYY/*.md` 压缩到
`data/history/markdown/YYYY.zip`，包内保留 `YYYY/文件名.md` 路径。
使用标准库 zipfile；保留原文件，重复运行替换同名包，临时文件写完后原子替换。
支持 `--source-dir` 和 `--data-dir`。按用户要求不核对内容哈希；
仅检查执行成功及压缩包数量和文件数量。不改动 JSON 归档和其他业务代码。

## 目标与范围

将仓库根目录 `YYYY/YYYY-MM-DD.md` 提取到 `data/history/`，保留原始 Markdown。
本次明确增加历史回填工具，独立于原采集方案中不处理历史 Markdown 的范围。
不改动在线采集的 `data/repos.json`、`data/snapshots/`、通知及用户正在修改的方案文档。

## 方案与接口

- `python3 archive_history.py` 默认以脚本目录为输入根、`data` 为输出根；
  `--source-dir`、`--data-dir` 可覆盖。仅扫描年份目录中的日期 Markdown。
- `data/history/repos.json` 保存去重仓库目录及历史首次、末次出现日期；
  `snapshots/YYYY/MM/YYYY-MM-DD.json` 保存原榜单顺序、排名、显示名称、简介、来源行号。
  `manifest.json` 保存文件、榜单、条目、仓库数量及日期范围。
- 兼容 `## 日期`、`###日期`、`####python`、头像标签和多行简介。
  以文件名确定归档日期，校验正文日期一致；仓库键从 GitHub URL 提取并转小写。
- 使用与在线快照相同的基础字段，额外记录 `source_type`、`source_file`、
  `source_sha256`。历史缺少采集时间、stars、forks、增长数及实际语言，均为 `null`；
  语言标题只作为 `language_filter`，不冒充实际语言。
- 每个原始条目均保留，包括历史榜内重复（不静默去重）；因此历史快照不调用在线
  采集器的唯一性校验。仓库目录仅去重元数据，快照保留逐次观察内容。
- 使用标准库，先完整解析校验所有输入再落盘；单文件临时写入后原子替换。
  同输入重复运行字节一致，不产生重复数据；只替换本工具生成的对应文件，不清理其他文件。

## 风险与取舍

Markdown 本身不规范，正文中类似标题的文本应保留在简介中；遇到无法识别的条目、
日期不符等结构错误应带文件及行号失败，不静默丢弃。
仅含合法日期标题的源文件（实际存在于 2018-03-26）保留为空快照，manifest 的
`empty_files` 统计此类源文件，不将它误判为完整榜单或静默跳过。
归档多文件并非事务，写入中断可重跑恢复；原 Markdown 始终保留。
重复运行不会删除已移出输入集的旧快照，manifest 统计当前输入集。

## 验证

使用 unittest 覆盖早期格式、多行简介、日期校验、非法链接、重复条目、
空榜、跨榜目录去重、重复运行、错误输入不写入、现有在线 JSON 不变。
全量运行后核对输入与快照文件数、逐条数量、源 SHA256、仓库引用和空缺指标，
运行现有测试与静态检查。
